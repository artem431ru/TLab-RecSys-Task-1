# Автоматическая генерация признаков для рекомендательной системы

Исследовательское задание на датасете **KION**: проверяю, можно ли улучшить рекомендации, автоматически создавая статистические признаки вместо ручного подбора каждого временного окна.

## Что сделано

1. Подготовил подвыборку из **10 000 пользователей** KION, сохранив доступную историю их взаимодействий. Для быстрого эксперимента использовал **1 500 пользователей** и несколько временных срезов.
2. Для каждого пользователя сформировал кандидатов из **300 популярных фильмов**, определённых только по прошлым событиям. Цель: предсказать взаимодействие в следующие **14 дней**.
3. Обучил **CatBoost** на ручных признаках: активность пользователя, популярность фильма, год выпуска, жанры и соответствие жанров интересам пользователя.
4. Реализовал генератор дополнительных признаков по окнам **3, 7, 14, 30 и 60 дней** и их отношениям. Сравнил группы признаков на валидационной выборке.
5. Проверил выбранную модель на более позднем тестовом периоде.

## Результаты

Метрики на **Test** (09–22 августа 2021 года):

| Модель | Recall@10 | NDCG@10 |
|---|---:|---:|
| Популярные фильмы | 0.1579 | 0.1001 |
| CatBoost, 8 ручных признаков | 0.1598 | 0.1149 |
| CatBoost, 11 ручных признаков | 0.1661 | 0.1209 |
| **CatBoost, 11 ручных + 6 автоматических** | **0.1695** | **0.1255** |

По сравнению с моделью на 11 ручных признаках **NDCG@10 вырос на 3,82%, Recall@10 — на 2,04%** (относительный прирост). Лучший вариант включал автоматически рассчитанные количества взаимодействий для дополнительных временных окон. Добавление *всех* автоматически созданных признаков не помогло, поэтому отбор важен.

## Как воспроизвести

Нужен Python и библиотеки из `requirements.txt`. Данные [KION_DATASET](https://github.com/irsafilo/KION_DATASET) скачиваются отдельно: файлы `interactions.csv`, `items.csv`, `users.csv` положить в `data/`.

В Windows PowerShell из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe prepare_data.py
.\.venv\Scripts\python.exe build_dataset.py
.\.venv\Scripts\python.exe train_baseline.py
.\.venv\Scripts\python.exe generate_features.py
.\.venv\Scripts\python.exe add_genre_features.py
.\.venv\Scripts\python.exe compare_features.py
.\.venv\Scripts\python.exe evaluate_test.py
```

**Важно:** в `build_dataset.py` должно быть задано **300 кандидатов** (`nlargest(300)`). Для полного воспроизведения дополнительных сравнений использовались также `candidate_recall.py`, `train_auto.py`, `select_features.py`, `train_genre.py` и `evaluate_baseline.py`.

## Ограничения

- У большинства пользователей короткая история, а в эксперименте отобрана более активная группа. Результаты нельзя автоматически переносить на всю аудиторию KION.
- `label=0` означает **отсутствие наблюдаемого взаимодействия**, а не явный отказ пользователя. В KION нет полного журнала показов рекомендаций.
- На тесте **371 пользователь с будущими просмотрами**, а покрытие реальных будущих просмотров списком кандидатов (`Candidate Recall@300`) составляет **39%**.
- Признаки рассчитаны по данным до момента предсказания, но `last_watch_dt` отражает последний просмотр пары user–item, поэтому история в KION не является полным журналом отдельных событий.
- Улучшение небольшое; статистическая значимость не оценивалась. Размер списка кандидатов ранее анализировался в том числе на тестовом периоде, поэтому независимость итогового теста имеет ограничение.

**Вывод:** в этом эксперименте автоматически сформированные временные агрегаты дали небольшое улучшение ранжирования, но добавление всех признаков подряд ухудшало качество. Результат показывает пользу осмысленного отбора, а не просто увеличения числа столбцов.
